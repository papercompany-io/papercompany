# 밸런스·규칙 변경 절차

## 1. 지금 규칙을 숫자로 설명

1. 규칙 코드(`src/core/*.ts`)와 수치(`src/data/*.json`)를 읽고, 문제를 **숫자로** 다시 씀.
   예: "레터 4개 = 관심 65 = 결정 확률 +26%p, 클럽딜 +15%p → 엔젤 기본 25%가 76%".
2. 문제 유형을 고름:
   - **지배 전략**: 공짜·무위험이라 항상 최선인 행동(다 보내기, 다 켜기). → 대가(한도·비용)나 조건(상대 취향·실제 지표)을 붙임.
   - **너무 이른 보상**: 준비 없이 들어오는 돈·고객. → 조건(기능·지표)을 거치게.
   - **정보 과다**: 플레이어가 수치를 보고 계산만 함. → 화면에서 숨기고 결과·답장으로 배우게(`screen-design` 스킬 3절).
3. 선택지를 2~4개로 정리해 추천 하나와 함께 사용자에게 묻고, 고른 것만 구현.

## 2. 구현 원칙

- 수치는 JSON에(`letterFx`처럼 이름 붙은 묶음 + `_note`), 코드는 그 값을 읽음. 하드코딩 숫자 금지.
- 효과 계산은 **순수 함수** 하나로(`letterGain`, `materialScore`, `canCharge` 예). 게임 로직과 화면 미리보기·결과 문구가 같은 함수를 씀.
- 새 데이터 필드는 타입(`src/core/data.ts`의 `FeatureFx`, `IndustryDef` 등)과 `_note`에 같이 적음. 예전 저장 호환(필드가 없을 때 기본값)을 확인.
- 플레이어가 배울 길을 같이 만듦: 답장 문구·힌트(`src/ui/hints.ts`)·미션 안내(`src/data/missions.json`)가 새 규칙을 알려 줘야 함.
- 봇(`scripts/sim/bot.ts`)이 새 규칙을 모르면 유능한 플레이어 흉내가 깨짐 → 우선순위·행동을 같이 고침(예: 결제 기능 우선).
- 결정 번호: `docs/ASSUMPTIONS.md` 마지막 + 1, 표에 "가정 / 이유(전후 측정)" 한 줄, 코드 주석에 같은 번호.

## 3. 측정

같은 시드로 **바꾸기 전 / 후**를 비교합니다. 한 가지만 바뀌게(다른 변경이 섞이면 임시로 그 데이터만 끄고 기준선을 잼, 끝나면 원복 확인).

```bash
npm run sim -- 10 1 --one 2>&1 | grep -E "마일스톤|끝:"
```

- 마일스톤(일): `mvp rev1 seed A B C ipo`, 끝: `ipo_exit / bankrupt`와 연수.
- 볼 것: 펀딩 성공 판 수, 첫 매출 시점, 이른 파산(1년 안) 수. 3판은 표본이 작으니 10판.
- 브라우저로 실제 사용자 저장에 대해 계산만 해 볼 땐 읽기 전용:
  `const fd = await import('/src/core/funding.ts'); fd.letterGain(window.__pc(), round, id, letter)`.

## 4. 마무리

- `npx tsc -p tsconfig.json --noEmit`
- 사용자에게: 바뀐 규칙(숫자), 측정 전후 표, 아직 남은 허점(예: "여전히 다 보내기가 손해는 아님")을 그대로.
