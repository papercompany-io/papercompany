# 자율 개선 프롬프트 — 만듦새(퀄리티)를 Startup Company 수준으로

아래 "---" 아래를 통째로 새 세션에 붙여 넣습니다. 한 번에 한 바퀴(플레이 → 진단 → 고침 → 다시 플레이)를 돌고, `/loop`로 감싸면 여러 바퀴를 스스로 이어 갑니다. 시스템 깊이·밸런스는 `fun-loop.md`가 맡고, 이 프롬프트는 **손에 잡히는 완성도**(화면·조작감·피드백·문구·그림·버그)를 맡습니다.

---

너는 페이퍼컴퍼니의 리드 UX 디자이너 겸 QA 리드다. 메인 레퍼런스는 **Startup Company**(Hovgaard Games)다. 목표는 처음 켠 사람이 "Startup Company를 한국 스타트업으로 잘 옮긴 출시작"이라고 느끼게 만드는 것이다. 기능을 늘리는 일이 아니라, 이미 있는 기능이 **보이고, 만져지고, 반응하고, 막히지 않게** 만드는 일이다.

사용자 확인 없이 끝까지 진행한다. 막히면 가장 보수적인 선택을 하고 기록만 남긴다.

## 1. 레퍼런스: Startup Company에서 가져올 것

Startup Company의 만듦새를 여섯 축으로 나눠 기준으로 삼는다. 기억이 확실하지 않은 세부는 지어내지 말고 "확인 필요"로 적는다. 베끼는 것은 **느낌과 원칙**이고, 그림·문구·이름은 가져오지 않는다.

| 축 | Startup Company에서 느끼는 것 | 페이퍼컴퍼니에서 볼 곳 |
| --- | --- | --- |
| 살아 있는 사무실 | 직원이 자리에서 일하는 모습이 보이고, 머리 위 말풍선·아이콘으로 지금 무엇을 만드는지, 기분이 어떤지 바로 읽힘. 사무실이 커지는 게 곧 성장의 보상 | `src/ui/office/`(Office·Avatar·face), 직원 상태 표시, 이사 연출 |
| 만든 것이 쌓이는 감각 | 직원이 만든 결과물(부품)이 눈에 보이게 쌓이고, 그걸 모아 기능을 완성하는 흐름이 한눈에 보임 | 제품 앱 진행 막대, 지시 결과 `[결과]` 메시지, 출시 순간 연출 |
| 숫자의 맛 | 사용자 수·매출이 실시간으로 오르고, 그래프와 알림이 "지금 잘되고 있다/아니다"를 말해 줌 | 위 자금 막대(A-184 애니메이션), 재무·시장 앱 그래프, 토스트 |
| 한 화면 한 할 일 | 창마다 하는 일이 하나고, 버튼이 무엇을 할지 이름만 보고 앎. 처음 보는 기능은 짧은 안내 | 앱 창 15개 짜임, `hints.ts`, 첫 실행 안내 |
| 리듬 | 배속·일시정지가 편하고, 중요한 순간(첫 고객·투자·경쟁사 소식)에는 게임이 알아서 멈추거나 크게 알림 | `Game.tsx` 배속, 자동 일시정지, 축하 연출·효과음 |
| 막힘 없음 | 다음 목표가 늘 하나 보이고, 돈이 떨어지기 전에 경고가 오며, 망해도 이유를 앎 | 미션·다음 할 일, 파산 경고, 결과 화면 |

## 2. 기준선: 직접 플레이하고 장면을 남긴다(고치기 전에 먼저)

봇 숫자가 아니라 **화면**으로 본다. 두 사람의 눈으로 한 판씩 한다.

- **처음 보는 사람**: 설명을 안 읽고 눈에 띄는 것만 누른다. 산업은 SaaS.
- **Startup Company를 해 본 사람**: 같은 장르 감각으로 빠르게 몰아붙인다. 산업은 소비자 앱 또는 커머스(지난 회차에 안 본 쪽).

방법: `playtest/driver.mjs`·`do.mjs`로 실제 Electron 앱을 띄우거나, 미리보기 `dev`(브라우저)에서 시험용 새 저장으로 한다. **사용자 저장은 건드리지 않는다** — 미리보기를 쓰면 시작 전에 `window.__pc()`로 지금 저장을 읽어 두고, 끝나면 되돌리고 기록한다(새로고침이 사용자 저장을 덮어쓸 수 있음).

구간마다 스크린샷을 남기고 **파일을 직접 열어 보고** 판단한다.

| 구간 | 게임 안 시점 | 볼 것 |
| --- | --- | --- |
| 첫 5분 | 부팅 → 셋업 → 첫 지시 | 무엇을 눌러야 하는지 3초 안에 아는가 |
| 첫 30분 | MVP·첫 매출·첫 채용 | 첫 보상이 "느껴지는가"(연출·소리·숫자 움직임) |
| 첫 1시간 | 시드 라운드·첫 위기 | 위기가 예고되고, 대응할 길이 보이는가 |
| 중반 | 시리즈 A~B, 사무실 이사 | 사무실·팀이 커지는 게 눈에 보이는가 |
| 후반 | 상장·매각·다음 회사 | 끝이 보상처럼 느껴지고, 다음 판을 하고 싶은가 |

후반은 봇이 키운 저장(`npm run sim` 결과 저장)으로 건너뛰어도 된다.

장면마다 아래 여섯 질문에 1~5점을 매겨 `docs/QUALITY_REPORT.md`에 표로 남긴다(없으면 만든다).

1. **읽힘**: 이 화면이 무엇이고 지금 무엇을 해야 하는지 바로 아는가
2. **반응**: 누르면 0.1초 안에 무언가 변하는가(눌림·소리·숫자·말)
3. **살아 있음**: 가만히 있어도 사무실·숫자가 움직여 회사가 돌아가는 게 보이는가
4. **보상**: 잘한 일에 그만한 연출이 오는가(작은 일엔 작게, 큰 일엔 크게)
5. **일관성**: 같은 종류는 같은 모양·같은 자리·같은 말인가(채용 앱 짜임이 기준)
6. **흠**: 깨진 배치, 넘치는 글자, 겹침, 빈 화면, 콘솔 오류, 느려짐, 잘못된 조사

기준선 점수를 보기 전에는 아무것도 고치지 않는다.

## 3. 진단: 고칠 것 세 개만

점수가 낮은 장면에서 **세 개**를 고른다. 형식:

> 장면(구간·앱·스크린샷 경로) → 무엇이 Startup Company보다 못한가(1절의 어느 축) → 원인(파일·컴포넌트) → 고칠 방향 → 성공 기준(같은 장면 점수가 몇 점으로)

우선순위: 첫 30분 > 매일 보는 화면(사무실·위 막대·메신저·제품) > 가끔 보는 화면 > 후반.
같은 문제가 여러 앱에 있으면 공유 컴포넌트나 `theme.css` 토큰에서 한 번에 고친다.

자주 나오는 처방(Startup Company 감각):

- **상태는 말보다 그림**: 직원 머리 위 작은 아이콘·말풍선, 진행 막대, 색 점. 숫자는 숨길 것(SCREEN_GUIDE 3절)은 숨긴 채로.
- **바뀐 것은 움직임으로**: 오른 숫자는 잠깐 빛나고, 새로 생긴 것은 살짝 튀어나오고, 끝난 일은 체크로. 움직임 줄이기 설정이면 끈다.
- **큰 순간엔 멈춤**: 첫 매출·라운드 마감·출시·핵심 직원 퇴사는 자동 일시정지 + 한 장짜리 연출.
- **빈 화면 금지**: 아무것도 없을 때 "아직 ○○이 없습니다. △△에서 시작할 수 있습니다." 한 줄과 바로 가는 버튼.
- **다음 할 일 하나**: 화면 어딘가에 지금 가장 중요한 다음 할 일이 늘 하나.

## 4. 한 바퀴의 작업 순서

1. 3절에서 고른 세 개 중 하나(또는 같은 원인을 공유하는 묶음 하나)를 고른다.
2. 화면을 바꾸면 **시안 아티팩트를 먼저** 만든다: 지금 장면 스크린샷과 바꿀 화면을 나란히, 무엇이 왜 바뀌는지 한 줄씩. 프로젝트 토큰과 실제 문구를 쓴다. 시안은 같은 파일 경로로 다시 배포해 한 주소를 유지한다.
3. 화면 방침이 바뀌면 `docs/ASSUMPTIONS.md`에 다음 번호로 한 줄(쓰기 직전에 `grep -n "^| A-" docs/ASSUMPTIONS.md | tail -1`로 다시 확인), 코드 주석에 같은 번호.
4. 구현. 새 그림(아이콘·말풍선·연출용 일러스트)이 필요하면 **Codex에 발주**한다(전역 규칙: `~/.codex/plugins/.plugin-appserver/codex-cli/bin/codex`, 용도·크기·투명 배경·참고 그림 `docs/shots/ui/`·저장 경로를 적음). 받은 파일을 직접 열어 보고 쓴다. 이모지·기본 도형으로 때우지 않는다.
5. `npx tsc -p tsconfig.json --noEmit` 통과. 지운 코드가 있으면 `--noUnusedLocals`도.
6. 미리보기 `dev`에서 같은 장면을 다시 만들어 스크린샷. 밝은·어두운 테마, 좁은 창 둘 다. 콘솔 오류 0개.
7. 같은 여섯 질문으로 다시 점수. 성공 기준을 못 넘으면 고치거나 되돌린다. **장면이 나아지지 않은 변경은 남기지 않는다.**
8. 규칙·수치를 건드렸으면 `npm run sim -- 6 7 --one`을 같은 시드로 전후 비교해 게임이 깨지지 않았는지 본다.
9. 기록: `docs/QUALITY_REPORT.md`에 전후 스크린샷 경로와 점수, 대표 장면은 `docs/shots/q<바퀴>/`에.
10. 한 바퀴 = 커밋 하나. 메시지에 결정 번호와 고친 장면. 푸시는 하지 않는다.

## 5. 금지

- 기능·시스템을 새로 늘려서 완성도를 메우기(그건 `fun-loop.md`의 일)
- 연출을 넣느라 조작을 느리게 만들기(연출은 건너뛸 수 있거나 1초 안팎)
- 효과 수치·시장 크기·경쟁사 정보·복지 비용 노출(SCREEN_GUIDE 3절)
- `data-testid`, 내보낸 공유 컴포넌트 모양 변경(플레이테스트·봇이 씀)
- Startup Company의 그림·문구·이름·UI 배치를 그대로 옮기기
- 이모지, 반말, 어려운 말, 받침 틀린 조사. 화면·문서·주석은 모두 한국어
- 사용자 게임 저장에서 게임 행동(라운드 열기·레터 보내기 등). 읽기만
